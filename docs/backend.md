# LabTrack backend

The selected setup is a local application with Supabase as its hosted database. The schema in `supabase/migrations/001_labtrack.sql` has been applied and SQL-verified in project `akudfcgksdjlipxxwfdu`. Set the server-only `SUPABASE_SECRET_KEY` in the local `.env` to connect the Node API. RLS and table/function grants deny browser access; the API retains the existing session and role checks. Changes are written in one versioned transaction, and conflicts reload the current snapshot before returning HTTP 409. See [the local Supabase guide](supabase-local.md). Configure only one hosted provider at a time; omit `MONGODB_URI` when using Supabase.

The Express API uses HttpOnly, SameSite=Strict cookies, random 256-bit session tokens and scrypt password hashes. Teacher and student access is checked on every protected route. The API rejects foreign mutation origins; configure `CLIENT_ORIGIN` only when a separate trusted frontend origin is needed. In production, HTTPS is required for Secure cookies.

Local development seeds 41 accounts with roll numbers 1–41, the two supplied three-task HTML labs and an example draft third lab. Student names come from the supplied marks-sheet image; rolls 16, 26, 27, 30, 34, 37 and 39 remain unnamed. The image's exam marks were not imported. Dates, scores, email aliases and submissions are demo data. Teacher: `teacher@labtrack.edu`; first student: roll number `1` (Muhammad Haroon); demo password: `LabTrack2026!`. Students can sign in using their roll number and password. Existing email aliases still work. Roll numbers are validated and unique in the range 1–41. Known sample names and legacy roll numbers migrate on startup without changing account IDs, emails, passwords, sessions or submission/grade references; later custom name edits are preserved. Demo shortcuts only work from loopback connections in development. Production disables shortcuts and requires a fresh, separate database or data directory and `ADMIN_EMAIL`/`ADMIN_PASSWORD` to initialize the real teacher account. Do not reuse the demo database for deployment.

Data persists in `.data/labtrack.json`, saved through an atomic replacement. Set `LABTRACK_DATA_DIR` for a different private directory, or `MONGODB_URI` to use MongoDB collections with transactional writes. MongoDB must run as a replica set or use Atlas so that transactions are available. Serve this implementation from one application process; cross-process state refresh and shared rate limiting are not implemented. Back up the data store before upgrades. Passwords are never returned to the browser. Sessions expire after seven days, and logout revokes the current session.

`npm run dev` runs the frontend and API. `npm run build` validates TypeScript and builds the frontend. `npm start` serves the built frontend and API from one Express process. Copy `.env.example` to `.env` to configure the server, or set environment variables in the shell. The server uses Node's built-in `.env` loader, so Node 22 or later is required. Development allows Vite on loopback port 5173; production accepts only the serving origin or the explicitly configured `CLIENT_ORIGIN`. `createApp()` in `server/app.ts` is asynchronous and does not listen; integration tests can close its store through `app.locals.store.close()`. `startServer()` in `server/index.ts` starts the listener independently.

Uploads accept UTF-8 HTML, HTM, CSS, JS, TXT and JSON; PNG, JPEG, GIF, WebP and ICO assets; and ZIP archives of these files. Relative paths survive folder and ZIP uploads. Limits are 60 files, 1 MB per text file and 4 MB total uploaded/extracted content; ZIP expansion is bounded before decompression. Traversal paths, hidden files, unsupported types, encrypted ZIPs, duplicates and invalid UTF-8 are rejected. Binary bytes remain private in the data store; the public submission includes image metadata. Downloads require authentication and use `Content-Disposition: attachment` plus `nosniff`. The frontend preview must isolate submitted HTML in a restricted sandbox and must not execute it in the teacher's origin.

Each student has one submission per lab task. Resubmission increases its revision, records a new timestamp and clears the prior grade so that changed work must be reviewed. Grade requests include the reviewed `revision` and fail with 409 if the student resubmitted meanwhile. Late submissions are accepted and visibly marked. Unpublished grades are hidden from students. Marks are constrained to the teacher-defined maximum. Similarity and requirement checks are advisory and never change marks or claim AI authorship. Original PDF/Word instructions can be attached as raw base64 with their filename and content type, up to 5 MB; the teacher defines and approves the requirement rules.

`GET /api/reports.csv?labId=...` exports one row per student, sorted numerically by roll number. Four columns match the reference: R. No, Name, Marks in Figure, Marks in Words. Heading rows identify the college, Lab N Marks Sheet (Fall 2026), BS Computer Science, Semester 7th and Web Engineering. Totals require all task grades to be saved; missing/incomplete totals remain blank, and zero grades remain zero. Saved draft grades are included in teacher exports. Cells are quoted and spreadsheet formula prefixes are escaped. `GET /api/reports/print?labId=...` provides the corresponding escaped HTML A4 print view. Both endpoints require teacher access.

Run `npm test` to check authorization, private grades, CSRF-origin rejection, grade validation, resubmission, CSV safety, persistence and bounded uploads. MongoDB connectivity and hosted deployment still require verification in the intended deployment environment.

`GET /api/labs/:id/analysis?taskId=...` is teacher-only and analyzes a single lab task. It parses each submitted project once, returns checklist/quality summaries and every positive pair, and reports scan limits. The UI flags only complete, substantial comparisons above the selected 70% or 50% threshold. Scores use the lower matching coverage of both tasks' normalized HTML/CSS/JavaScript fingerprints; repeated occurrences count, and small files contribute to coverage without independently producing a flag. Standard HTML scaffolding, configured required tags/text and quoted assignment examples are excluded. `GET /api/submissions/:id/analysis?peerId=...` supplies targeted matching excerpts for the full project comparison. Students cannot access other students' comparison results. No analysis endpoint mutates grades.
